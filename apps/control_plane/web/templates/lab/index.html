真实实验 · 在业务虚拟机终端执行

先启动持续业务请求，再在另一终端执行实验命令。命令保存原配置、记录证据并自动恢复；最长 180 秒。

① 容器进程中断

停止承载 Agent 的测试容器，独立客户端记录任务失败。该场景不等同于内核 OOM。

python3 -m scenarios.real_lab run process-failure --target layertrace-demo-agent --seconds 45 --output evidence/lab

② 模型计算资源瓶颈

限制模型容器 CPU 配额，观察节流和业务延迟；同虚拟机正常容器作为对照。

python3 -m scenarios.real_lab run cpu-quota --target layertrace-demo-model --cpus 0.10 --seconds 90 --output evidence/lab

③ 工具服务失败

工具返回 HTTP 503，沿同一任务的工具失败与任务失败事件关联诊断。

python3 -m scenarios.real_lab run tool-503 --target layertrace-demo-tool --seconds 45 --output evidence/lab
业务请求与独立恢复命令

正常业务与基线

docker compose --project-name layertrace-vm --env-file deploy/vm-probe/.env -f deploy/vm-probe/compose.yaml -f deploy/workload/compose.yaml run --rm demo-client python -m workloads.demo_agent.load_generator --count 35 --interval 1

单次请求（每次替换唯一任务 ID）

curl -s -X POST http://127.0.0.1:8091/tasks -H 'Content-Type: application/json' -d '{"task_id":"manual-UNIQUE","topic":"cpu"}'

独立恢复

python3 -m scenarios.real_lab restore --state evidence/lab/<run_id>/state.json

自动恢复后，仍须发起成功业务请求并等待事件单恢复稳定窗口。采集停止不代表故障消失。
